# Лабораторная работа №1. Цветовые модели

**Вариант:** четный — CMYK – RGB – HSV

## 1. Цель и задачи

Цель — разобраться, как устроены цветовые модели RGB, CMYK и HSV, и написать веб-приложение, в котором цвет можно задавать в любой из них, а две другие представления пересчитываются автоматически.

Что нужно было сделать:

- вывести и реализовать формулы перевода RGB ↔ CMYK и RGB ↔ HSV;
- дать три способа задания цвета: поля ввода, ползунки, палитра;
- пересчитывать остальные модели сразу при изменении любой компоненты;
- проверять корректность введенных значений.

## 2. Теория

### RGB
Аддитивная модель: цвет получается сложением света красного (R), зеленого (G) и синего (B) каналов. Каждая компонента — от 0 до 255. Используется в мониторах. (0, 0, 0) — черный, (255, 255, 255) — белый.

### CMYK
Субтрактивная модель печати: голубая (C), пурпурная (M), желтая (Y) краски поглощают часть спектра белого света, K — черная краска. В приложении каждая компонента — от 0 до 100 %.

Перевод RGB → CMYK (r, g, b нормированы в [0, 1]):

```
K = 1 − max(r, g, b)
C = (1 − r − K) / (1 − K)
M = (1 − g − K) / (1 − K)
Y = (1 − b − K) / (1 − K)        при K = 1:  C = M = Y = 0
```

Перевод CMYK → RGB:

```
R = 255 · (1 − C) · (1 − K)
G = 255 · (1 − M) · (1 − K)
B = 255 · (1 − Y) · (1 − K)
```

### HSV
Модель, близкая к тому, как человек описывает цвет:

- **H (Hue, тон)** — угол на цветовом круге, 0–360°: 0° красный, 120° зеленый, 240° синий;
- **S (Saturation, насыщенность)** — 0–100 %, от серого до чистого цвета;
- **V (Value, яркость)** — 0–100 %, от черного до максимально яркого.

Перевод RGB → HSV (max, min — наибольшее и наименьшее из r, g, b, d = max − min):

```
V = max
S = 0, если max = 0, иначе d / max
H = 0,                          если d = 0
H = 60 · ((g − b) / d mod 6),   если max = r
H = 60 · ((b − r) / d + 2),     если max = g
H = 60 · ((r − g) / d + 4),     если max = b
если H < 0, то H += 360
```

Перевод HSV → RGB:

```
i = floor(H / 60),  f = H / 60 − i
p = V · (1 − S)
q = V · (1 − S · f)
t = V · (1 − S · (1 − f))
(R, G, B) = (V, t, p), (q, V, p), (p, V, t), (p, q, V), (t, p, V), (V, p, q)   для i = 0…5
```

Если S = 0, цвет серый: R = G = B = 255 · V.

## 3. Реализация

Проект состоит из четырех файлов, сборщиков и библиотек нет:

| Файл | Назначение |
|---|---|
| `index.html` | разметка: окно предпросмотра и три блока — RGB, CMYK, HSV |
| `styles.css` | оформление |
| `convertFunctions.js` | функции `rgb2cmyk`, `cmyk2rgb`, `rgb2hsv`, `hsv2rgb` |
| `app.js` | работа с интерфейсом, проверка ввода, пересчет |

### Способы задания цвета
В каждом блоке есть поля ввода и ползунки на каждую компоненту. Помимо этого:

- RGB — палитра `<input type="color">` (системный выбор цвета);
- HSV — квадрат «насыщенность × яркость» при текущем тоне H (`canvas`, перетаскивание мышью);
- CMYK — квадрат «C × M» при текущих Y и K (`canvas`, перетаскивание мышью).

Таким образом, цвет в каждой из трех моделей можно задать тремя способами: числом, ползунком и выбором на палитре.

### Автоматический пересчет
Любое изменение вызывает функцию `changed(model)`, которая:

1. проверяет все поля модели (не пусто, число, диапазон от 0 до максимума компоненты); при ошибке подсвечивает поле красным и пишет подсказку под блоком;
2. переводит значения измененной модели в RGB (`toRgb`);
3. передает RGB в `showColor`, которая обновляет окно предпросмотра, палитру и поля/ползунки **двух других** моделей через `rgb2cmyk` и `rgb2hsv`;
4. перерисовывает палитры-квадраты с маркером текущего цвета.

RGB играет роль промежуточной модели: все переводы идут через нее. Модель-источник при пересчете не перезаписывается, поэтому значения, которые пользователь вводит, не «прыгают» из-за округления.

В полях значения округляются до целых, а сами вычисления идут с дробными числами, чтобы не накапливать погрешность.

## 5. Особенности и ограничения

- Переходы между моделями неоднозначны на краях: при K = 100 % значения C, M, Y не влияют на цвет, при S = 0 не влияет H, при V = 0 не влияют H и S. В таких случаях пересчет возвращает 0.
- CMYK здесь — простая математическая модель без цветовых профилей, поэтому на реальной печати цвета будут отличаться от экранных.
- Из-за округления до целых в полях обратный перевод может отличаться на единицу.

## 6. Вывод

В работе реализованы и проверены формулы перевода между RGB, CMYK и HSV, создано веб-приложение, в котором цвет задается в любой модели числом, ползунком или на палитре, а остальные представления пересчитываются сразу. Разобраны особенности моделей: аддитивная RGB для экранов, субтрактивная CMYK для печати и HSV, удобная для интуитивного выбора цвета.
